# The `doctor` checks

Generated by `just contracts` from `reachy_checks.CHECKS`. Do not edit this file
by hand: the contract-drift gate regenerates it and fails on any difference.

Every check `reachyctl doctor` runs and the provisioning verification role
performs is declared once, in that registry — reachyctl REQ-056. The identifiers
below are stable names: `doctor` prints one per row, `docs/ops/troubleshooting.md`
is keyed to them, and renaming one is a breaking change.

A check whose prerequisites were not supplied is **skipped**, not failed. The
"Needs" column is what has to be supplied for it to run at all.

### daemon.reachable

The robot's daemon is reachable and answering.

**Needs:** `daemon`

**Remediation, as `doctor` prints it:**

> Nothing here starts a daemon it cannot reach. Confirm the robot is powered on and answering at the address configured, and that its daemon is running.

### application.installed

The satellite is installed on the robot, at a known version.

**Needs:** `daemon`

**Remediation, as `doctor` prints it:**

> Install the satellite into the robot's application environment. Deployment installs it and then verifies the version actually running, rather than trusting the install.

```
reachyctl deploy
```

### application.running

The satellite is running on the robot.

**Needs:** `daemon`

**Remediation, as `doctor` prints it:**

> Start the application on the robot.

```
reachyctl app start
```

### groundstation.session

A session opens to the groundstation.

**Needs:** `groundstation`

**Remediation, as `doctor` prints it:**

> The groundstation refused the session or never answered. Confirm the service is running, that the configured endpoint reaches it, and that the credential presented is the one it expects; its readiness endpoint reports whether it finished warming up.

### groundstation.capabilities

The session agrees on at least one capability.

**Needs:** `groundstation`

**Remediation, as `doctor` prints it:**

> The session opened and the two sides have no capability in common, so nothing would answer a frame. Compare the versions installed on each side, and check the groundstation's capability health for one that failed to warm up.

### groundstation.round-trip

A frame goes out and comes back, and how long that took.

**Needs:** `groundstation`

**Remediation, as `doctor` prints it:**

> A session is up and no result came back to time. Read the groundstation's logs and capability health: a link this quiet is usually a capability that accepted the frame and produced nothing, rather than a network fault.

### models.files

Every pinned model file is present and unaltered.

**Needs:** `models`

**Remediation, as `doctor` prints it:**

> A model file is missing or is not the bytes the registry pins. Fetch them again into the directory the groundstation reads; the fetcher refuses anything whose digest does not match, so a run that succeeds leaves the reviewed weights in place.

```
python -m reachy_groundstation.models.fetch "$REACHY_GROUNDSTATION_MODELS_DIR"
```

### configuration.effective

The configuration in force matches what was declared.

**Needs:** `daemon`, `intent`

**Remediation, as `doctor` prints it:**

> The robot is not running the configuration that was declared. Apply the declaration; preview it first to see what changes.

```
reachyctl config apply
```

### home-assistant.identity

The satellite announces the Home Assistant identity declared.

**Needs:** `daemon`, `intent`

**Remediation, as `doctor` prints it:**

> The satellite announces an identity other than the declared one, so Home Assistant sees a second device and the entity history stays attached to the first. Apply the declared configuration to restore it. Whether Home Assistant's own device registry already holds a stale entry is a manual check, in its device list.

```
reachyctl config apply
```
